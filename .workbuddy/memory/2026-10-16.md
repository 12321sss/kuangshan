### 本轮实测踩的坑（都修了）
1. **EPSG:4326 下 from_origin 的 dx/dy 是「度」不是米** —— 造测试影像时按米填导致 y 范围变 -2533，面积差4个数量级。须按纬度换算。
2. **合成影像必须按真实 S2 波段号摆放**（B02=2 B03=3 B04=4 B08=8 B11=11），不能挤在前4波段，否则 classify 的 BANDS 表索引全错。
3. **背景值不能用均匀灰岩**：会同时满足「NDVI低」且「NDBI低」落进裸地判据，使裸地面积虚高一倍。矿区背景是林地，背景应给植被光谱。
4. **pixel_area_m2 = abs(a*e) 是平方度不是平方米** —— 会让像元数虚高12个数量级（实测 1.8e14）。必须 dx=dlon*111320*cos(lat)、dy=dlat*110540。
5. **统计量要用掩膜内均值**，不能全图均值（会被背景稀释，明明提取到高NDVI区诊断值却接近0）。
6. **from_bounds 要求 bounds 与影像同 CRS**，非4326必须先 transform_bounds，否则窗口算成 0x0 抛 Invalid dataset dimensions。
7. **RestTemplate.setConnectTimeout(Duration) 是 Spring 6.1+ 重载**，本项目用 SimpleClientHttpRequestFactory。
8. **回调必须透传上下文**：原先 inference 只回传几何/面积，projectId/imageryId 落库成 0，前端按项目过滤查不到结果。
9. RestTemplate/ApiResponse 泛型：`ApiResponse.ok(List)` 收 Object 需显式标注；`num()` 返回 double 不能赋 long（拆出 longVal()）。

## 第十一轮：修用户实测暴露的 3 个致命 bug（上传形同虚设）

用户反馈「上传了影像但没法用」「没有底图没法圈」，查出 3 个我上一轮遗漏的真 bug：

### 1. 上传大小限制（导致上传完全失败）
`application.yml` **没有 multipart 配置** → 走Spring Boot 默认 **单文件 1MB 上限**，
高分影像必然超。表现为「点了没反应」。
修复：`max-file-size/max-request-size: 2GB`；同时 Vite proxy 加 timeout/proxyTimeout 30min
（http-proxy 默认限制会截断大文件）。
实测 52.7MB 影像上传成功。

### 2. 底图加载不出来（用户截图只有地球）
**根因**：`tiandituBaseLayers()` 返回的是 `{ base, label }` **对象**，
我在 ImageryView 写成了 `.forEach((lyr) => ...)` —— 对对象调 forEach 直接抛错，底图根本没加。
ExtractView 的正确写法是解构 + `new ImageryLayer()` 包一层。
另：初始高度 40000m 太高看不到地物，改为 4000m + pitch -50° 斜俯视。
并新增「定位矿区」按钮 + 首次进入的操作指引浮层。

### 3. **上传的影像根本不能解译（最严重）**
`ExtractionService.submit` 里 `String satellite = img.getSource()`，
而白名单只有 SENTINEL2/LANDSAT9/GF2 —— 上传影像 source=UPLOAD，直接被拒：
`"该影像数据源暂不支持解译: UPLOAD"`。**上传功能等于白做**。
修复：
- 新增 `resolveSatellite(img, algoSatellite)`：上传影像回退 GF2 波段映射；
  请求可显式传 satellite（前端 UPLOAD 影像显示 GF2/GF7 下拉）
- SATELLITES 白名单加 GF7/UPLOAD；classify.BANDS 同步加 GF7/UPLOAD（与 GF2 同构四波段）
- 前端 submit 传 satellite

**实测**：52.7MB 上传 → 解译 → 1638.7ha / 覆盖率 99.92% / 256211 像元，全通。

###踩坑：手写阿里云 RPC 签名失败，官方 SDK 才对
第一版自己实现 RPC 签名，一直报 `SignatureDoesNotMatch`。
排查过程：服务端会回传真实待签串，发现 **Timestamp 的冒号必须保持 `%253A`**（双重编码状态），
用 unquote 还原成 `:` 必然签名失败。
**结论：阿里云 API 签名一律用官方 SDK，不要手写。**
- 另一个小坑：aliyun-python-sdk-core 部分版本返回 bytes 而非 dict，需先 json.loads 解码
- 验证脚本：`inference/probe_aliyun.py`（已改用 SDK）
- 依赖已固化：aliyun-python-sdk-core==2.16.1、aliyun-python-sdk-sts==3.1.3
