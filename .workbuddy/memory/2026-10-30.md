### 背景
`docs/26` 记录 C 阶段（20m 解缠）卡在 snaphu 只能 Linux 跑；那台电脑 WSL 被安全策略拦。
**但本机的 `wsl.exe` 也被同一条策略挡着**（不是沙箱，是「安全中心 → 命令安全 → 程序黑名单」），
我无法绕过，需用户手动放行。所以换了一条不依赖 WSL 的路。

### 方案：给解缠加纯 Python 后端（scikit-image）
- `scikit-image==0.26.0` 有 cp313 预编译轮子，Windows 直接可装
- 关键：`skimage.restoration.unwrap_phase` **支持 masked array** ——
  被 mask 的像元既不参与解缠也不影响邻域，低相干区不污染 AOI（这是能替代 snaphu 的技术前提）
- **`algorithms/unwrap.py` 新增**：
  - `unwrap_python(phase, corr, coh_min=0.05)` → Herráez 2D 解缠
  - `unwrap_auto(phase, corr)` → 有 snaphu 用 snaphu，否则自动退回 python（返回后端名便于追溯）
  - 注意：snaphu 调用**内联**而非 import `scripts.unwrap_linux`（scripts 无 `__init__.py`，跨包导入会失败）
- **新增 `scripts/unwrap.py`**（跨平台 CLI，`unwrap_linux.py` 保留兼容）：
  ```bash
  python scripts/unwrap.py --input GUNW.h5 --aoi w,s,e,n --out dir [--backend auto|snaphu|python]
  python scripts/unwrap.py --synthetic --out dir     # 无数据时自检
  ```
  产物：`unwrapped_phase.tif` / `los_disp_mm.tif` / `coherence.tif`（EPSG:4326、20m）
  + `unwrap_meta.json`（后端名/参数/位移统计），两条后端产物格式完全一致

### 精度实测
- 无噪声线性斜坡：解缠残差 **0.0000 弧度**（完全还原，常数偏置 0）
- 合成高斯隆起（峰值 -40mm）+ ±0.15 弧度噪声 + 低相干水块：
  RMS **2.92mm**、最大 14.60mm（≈7% 相对误差），低相干区全 NaN、邻域无污染
- GeoTIFF 校验：CRS EPSG:4326、320×240、像元约 20.9m、bounds 准确、nodata=nan

### 测试
`tests/test_unwrap_python.py` 5 个用例：线性精度 / 低相干掩膜 / 全无效 / 波长口径 / 端到端出产物
- **波长口径那个用例抓到一个理解错误**：我原以为 2π 对应 λ/4，
  实际双程观测 φ=4π/λ·ΔR，2π 对应单程位移 **λ/2 ≈ 122mm**。
  核对 `sbas.phase_to_los_mm` 确认两处公式一致（都是 φ·λ/4π），测试已锁死防漂移。
