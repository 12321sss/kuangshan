   - 旧脚本 `unwrap_linux.py` 里写的 `verbose=False` 是错的（从没跑过所以没发现）

### 踩坑清单（每个都花了不少时间）
1. **isce2 的 XML 属性名是 public_name，不是内部变量名**
   - `do_unwrap` → `do unwrap`（带空格）
   - `regionOfInterest` → `region of interest`
   - `demfilename` → `demFilename`（**大写 F**）
   - 写内部名报：`attribute corresponding to key "xx" is not present in the object`
   - 提取方法：正则 `public_name\s*=\s*'([^']+)'` 扫 topsApp.py

2. **Windows 写不了 WSL 路径**
   - `Path('/mnt/c/...')` 在 Windows 上是 WindowsPath，会把 `/` 规范化成 `\`，
     实际写到 `C:/mnt/c/...`
   - 解法：**XML 在 WSL 里生成**（用 ~/rs-venv/bin/python），路径用原生 Linux 形式

3. **中文路径导致 isce2 读不到 annotation**
   - 报 `No annotation xml file found`，但 annotation 目录里明明有 6 个 XML
   - 根因：isce2 内部 C/Fortran 组件对非 ASCII 路径支持差
   - 解法：**把 SAFE 复制到 ~/s1work（纯英文路径）**

4. **DEM 需要 isce2 配套元数据**
   - 只给 GeoTIFF 会报 `FileNotFoundError: xxx.tif.xml`
   - 解法：`gdal2isce_xml.py -i xicheng_dem.tif` → 生成 .xml + .vrt

5. **S1D 数据 burst 判定为 0（当前卡点）**
   - 现象：runTopo 里 `numberOfCommonBursts` 全 0 → boxes 空 → IndexError
   - 数据本身没问题：两景都是 9 bursts × 3 swaths，时间对齐到 0.1 秒，同 track/frame
   - 怀疑：S1D 是 2025 年新发射卫星，isce2 2.6.5 的 spacecraft/元数据兼容有问题
   - **解法（进行中）：换 S1A/S1B 历史数据**（茜坑 2022-2023 有 58 景 S1A，isce2 成熟支持）

### 关键技术结论
- isce2 处理必须放在**纯英文路径**下
- 单景 S1 SLC 4.79GB，2 景 9.6GB；解压后同等大小
- S1D（2025+）数据在 isce2 2.6.5 上可能不可用，优先用 S1A/S1B
