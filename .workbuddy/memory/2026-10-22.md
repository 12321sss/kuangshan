- FAILED 时把 inference 的 error 直接抛给用户

- 超时 60s → **600s**，每 5 秒界面显示「已等待 N 秒」

### ② 权限审计（发现 3 个真漏洞）
**漏洞1 传感器跨项目越权（高危）**：`SensorController` 4 个端点无 auth 无校验，
`list` 的 projectId 可不传返回全部项目；`/{id}/data|displacement|export` 知道 id 就能读。

**漏洞3 大屏汇总无归属校验**：`ScreenController.summary` 用 `projectService.get()` 不带用户，
任意 projectId 可看别人矿区名称/联系方式/告警数。已加 requireAccess。

## 修复：http://127.0.0.1:5173 打不开

**根因**：`vite.config.ts` 的 `server` 没配 `host`，Vite 默认只听 localhost，
而 Windows 上 localhost 优先解析到 **IPv6 ::1**。
`netstat` 证据：`TCP [::1]:5173 LISTENING`（只有 IPv6，没有 0.0.0.0/127.0.0.1）。
所以 localhost 能开、127.0.0.1 打不开。

**修复**：
- `server.host: '0.0.0.0'` → 监听 IPv4 全部网卡（127.0.0.1 + 局域网 IP 都通）
- 代理 target 从 `localhost` 改为 `127.0.0.1`（inference 8010 只监听 127.0.0.1，
  写 localhost 有解析到 ::1 的风险）

**验证**：0.0.0.0:5173 监听；127.0.0.1 / localhost 均 200；
`/api/auth/login` 经代理 200；`/sentinel/health` 经代理 200。

**注意**：localhost 与 127.0.0.1 是不同 origin，localStorage 不共享 → 换地址需重新登录。

**附**：后端 8080 是双栈（0.0.0.0 + [::]），inference 8010 仅 IPv4 127.0.0.1。

## 修复：内网穿透域名访问被 Vite 拦截

**报错**：`Blocked request. This host ("cn-hk-bgp-5.ofalias.net") is not allowed.`

**原因**：Vite 5+ 的 **DNS rebinding 防护**。默认 `allowedHosts` 只允许
`localhost` 与 IP 直连，用任何「域名」访问（穿透服务）都会被拦。

**修复**：`vite.config.ts` 加 `server.allowedHosts` 白名单，前导点匹配所有子域：
```ts
allowedHosts: ['.ofalias.net', '.ngrok.io', '.ngrok-free.app', '.cpolar.top',
               '.cpolar.cn', '.natappfree.cc', '.trycloudflare.com', '.loca.lt']
```
换穿透服务时把其域名后缀加进数组；仅本地演示可临时改 `true` 全放开（有 DNS rebinding 风险）。

**验证**（curl 带 Host 头模拟）：
- `Host: cn-hk-bgp-5.ofalias.net` → 200 ✅
- `Host: test.ofalias.net`（其它子域）→ 200 ✅（后缀匹配生效）
- `Host: evil.example.com` → 403 ✅（防护未丢）
- 本机 127.0.0.1 → 200

**附**：Vite 输出 Local http://localhost:5173 / Network http://192.168.0.13:5173。
穿透若走 https，HMR 的 ws 可能需另配 `hmr.clientPort`（当前未配，页面可正常用）。

## 本地端口穿透给外部演示

**结论：只需穿透 5173 一个端口**。前端所有请求走相对路径 `/api`、`/sentinel`，
由 Vite dev server 代理到 127.0.0.1:8080 / 8010，后端与 inference 无需暴露。
解译回调走 `http://localhost:8080/...`（本机内部），不受穿透影响。

**新增 TUNNEL 演示模式**（vite.config.ts）：
`TUNNEL=1 npm run dev` 时
- `allowedHosts: true`（穿透域名随机，省得每次改白名单）
- `hmr: { protocol:'wss', clientPort:443 }`（https 穿透下热更新 ws 才通）
不设该变量时保持本地开发行为（白名单域名 + 默认 HMR）。
**改 vite.config.ts 必须重启 dev server**（不热更新）。
