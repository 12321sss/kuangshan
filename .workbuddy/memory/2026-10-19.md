## 第十八轮：修查询影像 422 + el-radio 废弃警告

用户实测「遥感提取」页点「查询影像」报 422 错误。

### 根因：字段命名不匹配
前端 `sentinel.ts` 发的是**蛇形**字段（start_date/end_date/max_cloud/class_type/min_area_px），
而我在 inference main.py 重写时把 `OnlineSearchRequest`/`OnlineExtractRequest` 定义成了**驼峰**
（startDate/endDate/maxCloud/classType/minAreaPx）。FastAPI Pydantic 默认严格匹配字段名 → 422。

修法：给 Pydantic 字段加 `alias`（蛇形别名）+ `model_config = {"populate_by_name": True}`，
这样**蛇形和驼峰都能接受**，前端不用改、后端内部引用仍是驼峰字段名（改动最小）。
实测：search 和 preview 都返回 200，真彩 base64 35KB 正常。

### el-radio label 废弃警告
AnalysisView.vue 用了旧 API `label=""`/`label="PIT"`（label 当 value），Element Plus 3.0 会废弃。
改为 `value=""`/`value="PIT"`。其余页面（AlarmLogView/DashboardView/MonitorDataView 等）已经是 value，无此问题。

### 教训
- FastAPI 字段名是驼峰还是蛇形，必须和前端请求体**逐字对齐**，否则 422 且不报具体字段。
  用 alias 双兼容是最稳的。
- 前后端命名约定：Python/FastAPI 惯例蛇形，但本项目 Java 侧是驼峰，inference 夹在中间——
  统一用 alias 桥接，别在两边各改一遍。

## 第十九轮：修「开始提取」422（同步/异步接口职责混乱）

用户点「开始提取」报 422。根因是**接口职责混淆**：

我把 `/api/v1/sentinel/extract` 做成了**异步回调**（callbackUrl 必填 + projectId），
但前端 RemoteExtractView 的 `sentinelApi.extract` 是**同步直连**（增量包原设计，不发 callbackUrl）。
两边语义冲突 → 前端不发 callbackUrl → Pydantic 校验「Field required」→ 422。

### 正确拆分（两个接口各司其职）
- `/api/v1/sentinel/extract`（**同步**）：前端「遥感提取」页直连，算完直接返回 features+覆盖率，
  前端立即上图。**无 callbackUrl**。落库由前端调 Java /extractions/save。
- `/api/v1/sentinel/extract-async`（**异步**）：Java submit-online 专用，带 callbackUrl，
  算完回调 /api/callback/task-complete 落库。

对应改动：
- inference：OnlineExtractRequest 拆掉 callbackUrl/projectId/name（改为 AsyncExtractRequest 承载），
  新增 /extract（同步，直接返回 result）和 /extract-async（异步，原逻辑）
- Java ExtractionService.submitOnline 改调 /extract-async

### 实测
- 同步 extract：200，12.3s 返回，覆盖率 93.95%、1 要素、scene_id + datetime 齐全
- 异步 extract-async：Java submit-online 返回 taskId 正常

### 教训
- 同一个 URL 不能既当同步接口又当异步接口——前端直连（同步）和 Java 代理（异步回调）
  是两种不同契约，必须拆成两个端点，否则必有一方字段校验失败（422）。
- 增量包原始 sentinel.ts 是同步直连设计，我集成时把后端 extract 改成了异步，
  没同步改前端，导致字段错位。**改接口契约必须前后端一起改**。

## 第二十一轮：UI 修复——页签压缩 + 侧边栏折叠

用户反馈（截图）：
1. 顶部页签栏放大后页签缩到一起
2. 左侧栏希望可折叠

### 修复
1. **页签压缩**：.tab 缺 flex-shrink:0，flex 容器里子项默认可被压缩——窗口放大/页签多时
   每个页签被挤扁。加 flex-shrink:0 后超出部分由 .tabs-bar 的 overflow-x:auto 横向滚动。
2. **侧边栏折叠**：sidebar 底部加「收起菜单」按钮（带 Fold 图标，margin-top:auto 贴底），
   收起后 width:0 隐藏；页签栏左侧出现 Expand 展开按钮恢复。
   sidebarCollapsed ref 控制，transition width 0.2s。

### 教训
flex 布局中「可滚动的子项列表」必须给子项 flex-shrink:0，否则容器不滚动而是压扁子项——
这是 overflow-x:auto 不生效的最常见原因。
