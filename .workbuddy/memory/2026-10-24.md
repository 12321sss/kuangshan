## 修复：GIS 大屏右下角「最近解译记录」内容溢出

**现象**：右下角面板的记录列表顶出边界，最后一行被切掉一半。

**根因**：`.recent-panel` 只设了 `max-height: 246px`，
但父容器 `.panel-col.right` 是 `display:flex; flex-direction:column`，
**flex 子项默认 `min-height: auto`**，不会收缩到内容以下；
同时 `.recent-table` 的 `overflow-y: auto` 因为**没有确定高度**而不生效。
→ 内容照样溢出面板，`max-height` 只是裁了个寂寞。

**修复（标准 flex 滚动三件套）**：
```css
.recent-panel {
  flex: 0 1 auto;      /* 高度跟内容走，记录多到上限后滚动；空间不足可收缩 */
  min-height: 0;       /* 关键：允许 flex 子项被压缩 */
  max-height: 246px;
  display: flex; flex-direction: column;
  overflow: hidden;    /* 裁掉圆角外溢出 */
}
.recent-panel .panel-title { flex-shrink: 0; }  /* 标题不被压缩 */
.recent-table {
  flex: 1; min-height: 0;   /* 关键：让 overflow-y 生效 */
  overflow-y: auto;
  padding-right: 3px;       /* 给滚动条留位，别压住面积数字 */
  scrollbar-width: thin;
}
```
另加 4px 暗色细滚动条（`::-webkit-scrollbar`），默认滚动条在深色大屏上太丑。

**关键经验**：flex 容器里想做内部滚动，必须同时给
「父：`min-height:0` + `overflow:hidden`」和「子：`flex:1` + `min-height:0` + `overflow:auto`」，
只写 `max-height` 一定失效。

## 修复：角色授权缺少项目授权，新建角色看不到任何项目

**用户反馈**：角色授权里没有「工程项目」授权，所以新建角色的用户无法查看项目。

**核实**（DB 查证）：
- `yanshi`、`LYY` 两个账号 **project_members 里没有任何记录** → 登录后项目列表为空
- `admin` 也不在成员表，但 isAdmin 直通所以能看全部
- 原逻辑：`listForUser` 只按 `p.getMembers().contains(username)` 过滤
  → 项目可见性**完全依赖手动加成员**，新建角色必然踩坑

### 方案：角色级项目可见范围（三级 + 并集）

**Role 实体加两字段**：
- `projectScope`: `ALL` / `SPECIFIC` / `NONE`（默认 NONE，向后兼容）
- `projectIds`: JSON 字符串数组

**可见性 = 角色范围 ∪ 个人成员**（并集，不是覆盖）
- `ALL` → 全部
- `SPECIFIC` → projectIds 里的项目
- `NONE` → 只看个人成员（旧行为）
- **ADMIN 角色在代码里恒为 ALL**（`toScope` 里硬编码），防误配锁死管理员

**后端改动**：
- `Role.java` 加 2 字段 + getter/setter
- `RoleStore.create/update` 保存新字段 + `validateScope()` 校验取值
- `ProjectService` 注入 `UserRepository` + `RoleStore`，新增
  `resolveScope(username)` / `toScope(Role)` / `canSee(...)`；
  `listForUser` 和 `requireAccess` 共用同一判定（签名未改，7 处调用点无需动）
- 角色被删/数据异常时 `resolveScope` catch 后降级为「只看个人成员」，不阻断主流程

**前端改动（RolesView.vue）**：
- 表单加「可见项目」：全部 / 指定项目（多选）/ 仅按个人成员 + 动态说明文案
- `scopeMode` 必须写成**可写 computed**（get/set），否则 radio-group 的 v-model 会报只读
- 选 SPECIFIC 但没勾项目时保存前拦截提示
- 角色列表加「可见项目」列（全部 / N 个 / 未配置红标）
- `Role` 类型加 projectScope/projectIds

**数据迁移**（JPA 自动加列 `project_scope`、`project_ids`）：
| 角色 | 迁移后 |
|---|---|
| ADMIN | ALL |
| ANALYST | SPECIFIC ["1","2"] |
| MANAGER | SPECIFIC ["1","2","3","4"] |
| VIEWER | SPECIFIC ["1"] |
| Yanshi | SPECIFIC ["1","2","3","4"] ← 原先 0 个 |
| LYY | SPECIFIC（用户在界面勾了 1、3） |

### 验证

yanshi   SPECIFIC   → 4 个项目（修复前 0）

越权防护有效：analyst 访问项目 3/4 影像 → **403**

### 经验
「角色能做什么」和「能看哪个项目」是两个正交维度。只做前者时，
新建角色的人必然看不到数据，而且这个坑很隐蔽——菜单有、页面打开是空的。
把项目范围也挂到角色上，新用户零配置就能用，同时保留个人成员做细粒度补充。
