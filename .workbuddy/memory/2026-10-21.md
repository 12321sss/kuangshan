## 设计文档：边坡失稳评估与分尺度监测（docs/13，草案）

用户提出"DEM 怎么和遥感提取结合判断坍塌/滑坡"、"两期对比看变化和加速度"、"一周一对比做实时判断"，讨论两轮后要求写入文档。

### 核心方法论结论（这轮讨论的最大价值）
1. **纠正"坡陡就滑"**：真正决定失稳的是三种力学扰动 —— 坡脚被切(under-cutting，最危险且最易被忽略) /
   坡体被削 / 坡顶堆载。三者都能用「遥感边界 + DEM」直接算，这才是两者真正的结合点。
2. **引入边坡单元（Slope Unit）**：坡度掩膜 ∩ 提取边界 → 坡向聚类 + 反地形分水岭。
   核心指标 = 坡脚距采坑边界距离 + 坡脚被切比例 + 剖面曲率 + 坡高。
   六维模型的形态维度应从"全矿区平均"改为"取最差 3 个单元"（最弱一环逻辑，平均会稀释危险单元）。
3. **加速度不可直接算**：DEM 误差 ε 经二阶差分放大为 2ε/Δt²，季度尺度误差达 160 m/年²，
   比真实值大三个数量级。改用 **Fukuzono 倒数速度法**（1/v 线性外推至 0 得失稳时刻），
   仅在加速蠕变段有效，只能作预警参考。
4. **周尺度三个硬约束**（重要，回答"一周一对比是否可行"）：
   - 重访≠可用：Sentinel-2 理论 5 天，赣南雨季常整月无无云影像
   - 一周采坑推进 0.4-1 m，仅 10m 像元的 1/10~1/25，面积统计全是噪声
   - 光学看不到"滑动"（颜色形状不变），形变只能靠 InSAR
   → 周尺度正确形态是**事件驱动**：每周查影像可用性 → 有则做突变斑块检测 → 人工确认；
     绝不能在无影像时显示"本周无变化"（"没数据"≠"没变化"）
5. **Terrarium 是静态 DEM**，不随开采更新 → **做不了 DEM 时序差分**（L4 必须等无人机 DSM 或立体像对）
6. **六层监测 L1-L6**：L1 可用性检查✅ L2 突变检测✅ L3 覆盖趋势✅(已有) L4 DEM差分❌ L5 InSAR❌ L6 雨量❌

## 阶段一功能完成：边坡单元 + 三区扰动 + 接入六维模型

### 算法（inference/slope.py，约 400 行）
- 单元划分：扰动边界 ∩ 坡度≥10° → scipy.ndimage.label 连通域 → 按坡向 8 方位二次拆分
  - **阈值 15°→10°**：实测丘陵矿区平均坡度仅 6.4°、P90 14.3°，15° 会把真实边坡整片滤掉
- 三区扰动：
  - ① 切脚：坡脚（像元最低点）到采坑边界最短距离 + 坡脚周围被切比例
  - ② 削坡：坡度 + 拉普拉斯曲率（负=凸形坡，坡脚应力集中）
  - ③ 堆载：坡顶 20m 缓冲内是否有排土场/尾矿 —— **仅对采坑单元有意义**
- 分级：切脚<10m 且坡高>50m → 高；堆体坡高>30m 且坡度>25° → 较高（堆体自身判据）
- 返回 diagnostics（坡度分布 + 达标像元数），解释「为什么单元少」

### 修掉一个逻辑错误
最初"坡顶堆载"判据用于所有设施 → 排土场单元 100% 标记"有堆载"（堆体自身就是载，同义反复）。
改为仅采坑单元生效，堆体改走"堆高+坡角"判据。

### 六维模型接入
- risk.py 新增 `_unit_risk_score()`：切脚 50 分（主导）+ 切脚比例 15 + 坡高 20 + 坡度 15 + 堆载 5 + 凸坡 3
- `_terrain_risk(terrain, pit_ratio, units)`：有单元取**最差 3 个**聚合（最弱一环逻辑），无单元退回全区统计
- 返回 `basis: "slope_units" | "fallback"`，前端显示计算依据标签
- SafetyController 加 `withSlope` 参数（默认 false，避免每次多 10-30 秒）；失败自动降级不阻断

没有 `CesiumMath` 这个导出名；项目既有写法是 `import { Math as CesiumMath } from 'cesium'`（ImageryView 就是这么写的），
我新加代码时直接写了 `CesiumMath` 导致模块解析失败。
修法：改回 `Math as CesiumMath`。
**记住：Cesium 的 Math 工具类导入必须写 `Math as CesiumMath`，写 `CesiumMath` 会运行时报错（vite build 不报，dev 才炸）。**

## 第二批：空间关系 6 项 + 趋势研判/复绿（不依赖外部数据）

### 新增 inference/spatial.py（约 470 行）
六项"两个图层叠一下就有结论"的分析，全部用现成解译结果 + DEM：
- B6 坑内积水：水体∩采坑，占采坑 ≥15% 判高（排水失效/突水）
- B7 尾矿库水面：本期 vs 上一期，扩大 ≥20% 判高（溃坝前兆）
- B8 排土场汇流：排土场∩低洼汇水区（flow_proxy 的 P85），压占 ≥25% 判较高
- B9 道路切坡：道路∩坡度≥阈值，≥20% 判较高
- C4 生态缓冲区：环带缓冲区内/外植被占比差
- A3 采坑形态：面积/周长/形状指数 4πA/P²/等效半径/边界推进（advanceM）

### 两个关键实现坑（重要）
1. **DEM 窗口必须按缓冲区半径外扩**，否则缓冲区落在窗口外，栅格化后为 0 像元 → 统计为 0。
2. **几何叠加用 rasterize 对齐 DEM 网格**，不用逐多边形求交：解译结果常有上千碎斑，
   shapely 两两求交会慢到不可用；栅格化后逐像素布尔运算又快又稳。
   代价是有半像元误差（all_touched=True 会略微高估面积）。

### 两个"会得出错误结论"的口径修正（必须记住）
1. **植被只在某个 AOI 内提取过，缓冲区常在 AOI 之外**。直接算"缓冲区植被占比"会得出
   "缓冲区一片荒芜"的假结论（实测 3.6% vs 矿区 55.4%）。已加覆盖度校验：
   植被外包框覆盖缓冲区 <80% → 判"不可用"并说明"需在外扩范围重新提取"。
2. `_item()` 的 `available` 原先默认 True，"不可用"项被当成低风险计入统计。改为 level=="不可用" 时自动 False。

### 趋势研判（B4）+ 持续复绿（C3）
`/api/analysis/trend-judgement`（AnalysisController）：
- 各期扰动/采坑/植被面积（同 AOI 同期取最新，按 date 优先）
- 最近两期扰动方向：±10% 阈值 → 扩张/收缩/基本稳定
- 复绿：按 AOI 植被序列，0.5% 容差算连续上升期数；连续≥3 期且累计≥5% 才判"持续复绿"，
  且强制注明"不等于生态修复成功"；不足 3 期返回"待观察"，不硬下结论
- 前端：数据分析页新增「趋势研判与复绿判定」卡片

## 修：AOI 加载 / 监督分类影像可读性 / 时序混播

用户反馈三处问题，逐一定位修复。

### 1. 在线解译 / 本地解译「加载不了上传的 AOI」
根因：两页都只有「圈选」和「复用上次」，没有从边界库选。pending_aoi 只在从边界管理点「用于提取」时才写入，
且在线解译只在 onMounted 读一次。

选中后取详情外环 → 设为 AOI → 相机 flyTo 到该范围。
在线解译抽出 `setAoiAndFly()` 供 pending_aoi 与下拉复用。

### 2. 监督分类影像像素太差、没法选点
根因：AOI 只有 34.6 ha（约 59×59 像素，10m 影像），且默认 1 倍显示时图很小，
用户放大后看到的是放大的 10m 像元——不是渲染坏了，是数据本身就这么粗。
修：
- 加载后自动 `fitToBox()` 铺满可视区（上限 12 倍），加「适应窗口」按钮
- 卡片下方加**分辨率诊断条**：显示 `W×H 像素 / 每像素约 X m`；
  小于 60 像素时转黄并提示「区域太小，建议导入更大边界或换更高分辨率影像」
- 新增**真彩/假彩(近红外)**切换：假彩更容易区分植被与裸地

### 3. 时序播放把所有种类混在一起播
根因（后端 bug）：`/api/timeseries/groups` 只按 `aoiSignature` 分组，
同一块地的植被/裸地/采坑被当成同一序列，播放时看着像时间变化，实为不同地物。
修：
- 分组键改为 `区域指纹|地物类型`
- 详情接口 `/timeseries/{signature}` 解析组合键（也兼容纯指纹），按类型过滤
- 面板下拉与标题显示类型中文名（露天采坑/排土场/尾矿/裸地扰动/道路/植被/水体）

### 4. 顺带：本地解译类型只有 5 类
补齐为七类（加 TAILINGS/ROAD），并每个类型加「判别依据」提示；
经查 `classify.py` 本地路径对 PIT/DUMP/TAILINGS 统一按人工扰动裸地提取（无 DEM 无法细分），
提示里已如实说明「细分请用监督分类」。

### 经验
- 前端「某功能用不了」先查入口有没有做，别急着怀疑算法
- 时序类功能的分组键必须带**对象维度**（类型/AOI），只按空间指纹分组必然混播
- 小区域（<1km²）在 10m 影像上像素极少，必须把"多少像素/每像素多少米"显式告诉用户
