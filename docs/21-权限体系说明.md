# 权限体系说明（RBAC）

> 更新时间：2026-10-22
> 涉及：`PermCatalog.java`（权限点目录）、`RoleStore`、`PermissionGuard`、前端菜单与角色管理页

---

## 一、模型：两层权限 + 一层数据隔离

```
登录态（JWT）
   ↓
① 页面权限 page:xxx   —— 控制左侧菜单是否出现、路由是否可进
② 操作权限 action:xxx —— 控制按钮/接口是否可执行（上传、删除、评估…）
   ↓
③ 项目可见范围 —— 角色配置的可见项目 ∪ 个人成员关系（project_members）
```

> ③ 在 2026-10-24 补充了「角色级」配置：原先只能靠个人成员关系，
> 导致新建角色的用户登录后一个项目都看不到。详见第九节。

管理员（角色 code = `ADMIN`）在 ③ 上直通，但 ① ② 仍按角色表里的权限走。

## 二、权限点清单（2026-10-22 细化后）

此前 `page:analysis` 一个点管着 8 个页面、`page:extract` 管着 5 个，

### 页面权限（27 项 + 1）

| 分组 | 权限点 |
|---|---|
| 总览 | `page:dashboard` 总览 |
| 数据准备 | `page:imagery` 影像库、`page:boundary` 边界管理 |
| 解译作业 | `page:extract` 在线解译、`page:classify` 监督分类、`page:extract-local` 本地解译 |
| 持续监测 | `page:change-monitor` 变化监测 |
| 结果比对 | `page:compare` 数据对比、`page:fusion` 结果融合 |
| 监测告警 | `page:monitor` 设备监测、`page:ops-stations` 站点监控、`page:warning-rules` 预警设置、`page:warning-alarms` 告警日志 |
| 变化分析 | `page:analysis` 时序与构成 |
| 安全与生态评估 | `page:safety` 综合安全评估、`page:slope` 边坡单元、`page:spatial` 空间关系、`page:terrain` 地形分析、`page:ecology` 生态指数 |
| 成果输出 | `page:report` 报告生成、`page:screen` GIS 大屏 |
| 平台管理 | `page:projects` 项目管理、`page:users` 用户中心、`page:roles` 角色管理、`page:audit-logs` 操作日志、`page:dict` 数据字典、`page:health` 系统健康、`page:trash` 回收站 |

### 操作权限（18 项）

| 分组 | 权限点 |
|---|---|
| 数据准备 | `action:imagery-manage` 影像上传/删除、`action:boundary-manage` 边界导入/删除 |
| 解译作业 | `action:extract-manage` 解译执行/删除、`action:classify-manage` 监督分类训练/样本入库、`action:watch-manage` 关注区新增/删除 |
| 安全与生态评估 | `action:safety-evaluate` 执行安全评估、`action:ecology-evaluate` 计算生态指数、`action:terrain-analyze` 地形分析 |
| 成果输出 | `action:report-generate` 生成/下载报告、`action:export` 导出 GeoJSON/GeoTIFF/CSV |
| 监测告警 | `action:alarm-ack` 告警确认、`action:rule-edit` 预警规则编辑、`action:station-manage` 站点增删改 |
| 平台管理 | `action:project-manage` 项目增删改/成员分配、`action:user-manage` 用户增删改、`action:role-manage` 角色增删改、`action:dict-manage` 数据字典维护、`action:trash-manage` 回收站恢复/彻底删除 |

> **向后兼容**：旧的 `page:extract` / `page:analysis` 等编码全部保留（含义收窄为「在线解译」「时序与构成」），
> 所以老角色的数据不会因编码消失而报错。

## 四、怎么配一个新角色

1. 进「平台管理 → 角色管理」→ 新增角色
2. 角色编码：**大写字母 + 下划线**，如 `SAFETY_OFFICER`（这是角色标识，不是登录名）
3. 页面权限：按分组勾选，组头的复选框可**整组全选/清空**
4. 操作权限：同上
5. 保存后到「用户中心」给用户分配该角色

> 角色编码一旦被用户引用就不能随便改；想改名请改「角色名」，编码保持不变。

## 五、常见问题

### Q1：新建用户后登录报 401？

**最常见原因：用户名和姓名填反了。**

- **用户名** = 登录账号，只能用英文/数字/下划线/点/中划线，2~32 位（如 `yanshi`）
- **姓名** = 界面显示的名字，可用中文（如 `演示账号`）

2026-10-22 起前端已加格式校验 + 字段提示，创建成功后还会提示「登录账号是 XXX（不是姓名 YYY）」。
历史上已产生一条填反的数据（username=`演示`、displayName=`yanshi`），已修正为 username=`yanshi`。

### Q2：新建用户后看不到菜单？

该用户所属**角色**的页面权限为空。去角色管理给这个角色勾上页面权限。

### Q3：能看菜单但点按钮提示「当前角色无权执行此操作」？

页面权限有了，但缺对应的**操作权限**。例如能进「生态指数」页（`page:ecology`），
但点「计算」需要 `action:ecology-evaluate`。

### Q4：能不能只让某个角色看某几个项目？

可以。角色决定「能做什么」，`project_members` 决定「能看哪些项目」。
在「项目管理 → 成员」里给用户分配项目即可。

### Q5：改了角色权限，用户什么时候生效？

**下次请求即生效**——权限是每次请求实时从角色表读的，不需要重新登录。
但**菜单**是登录时下发的，所以菜单变化需要刷新页面（F5）才看到。

## 六、接口约定

| 接口 | 说明 |
|---|---|
| `GET /api/roles/catalog` | 返回 `{pages:[{code,name,group}], actions:[{code,name,group}]}` |
| `GET /api/roles` | 角色列表（含 pagePerms/actionPerms） |
| `POST /api/roles` | 新建角色（后端 `validatePerms` 校验编码必须存在于目录中） |
| `PUT /api/roles/{code}` | 修改角色权限 |

> 注意：后端 `RoleStore.validatePerms` 会拒绝目录里不存在的权限编码。
> 新增权限点必须同时改 `PermCatalog`，否则保存时会报「非法权限点」。

## 九、角色级项目可见范围（2026-10-24 新增）

### 为什么加

此前项目可见性**只**由 `project_members` 决定。新建角色 → 新建用户 → 该用户登录后
「项目管理」里空无一物，必须先去「项目管理 → 成员」逐个添加。
实测确认：`yanshi`、`LYY` 两个账号当时都不在任何项目里，登录后看不到任何数据。

### 模型：三级取值 + 并集

角色上新增两个字段（`roles.project_scope` / `roles.project_ids`）：

| 取值 | 含义 | 适用 |
|---|---|---|
| `ALL` | 该角色用户可见全部项目 | 管理员、总监级 |
| `SPECIFIC` | 仅可见 `project_ids` 里勾选的项目 | 大多数业务角色 |
| `NONE` | 不预设，只按个人成员关系（旧行为） | 需要逐人精细控制的场景 |

**最终可见 = 角色范围 ∪ 个人成员**（并集，不是覆盖）。
这样角色配了项目的人，再被单独加进别的项目也不会丢。

管理员（角色 code = `ADMIN`）在代码里恒为 `ALL`，不依赖数据库配置，防止误配把管理员锁在外面。

### 配置入口

「平台管理 → 角色管理」→ 编辑角色 → **可见项目**：

- 全部项目 / 指定项目（多选）/ 仅按个人成员
- 选「指定项目」但一个都没勾时，保存会被拦下并提示
- 角色列表新增「可见项目」列：`全部` / `N 个` / `未配置`（红色，提示需要配）

### 判定逻辑

`ProjectService.listForUser` 与 `requireAccess` 共用同一套判定：

```java
// 角色 ALL → 全部
// 否则：项目在角色 project_ids 里，或 用户在 project.members 里 → 可见
private static boolean canSee(Project p, String username, ProjectScope scope) {
    if (scope.ids().contains(p.getId())) return true;
    return p.getMembers().contains(username);
}
```

### 迁移记录

| 角色 | 原状态 | 迁移后 |
|---|---|---|
| ADMIN | 仅靠 isAdmin 判断 | `ALL` |
| ANALYST | 成员：项目 1,2 | `SPECIFIC ["1","2"]` |
| MANAGER | 成员：项目 1,2,3,4 | `SPECIFIC ["1","2","3","4"]` |
| VIEWER | 成员：项目 1 | `SPECIFIC ["1"]` |
| Yanshi | **无任何成员** → 看不到项目 | `SPECIFIC ["1","2","3","4"]` |
| LYY | **无任何成员** → 看不到项目 | `SPECIFIC`（按界面勾选为准） |

### 验证结果

```
admin    ALL              → 4 个项目
yanshi   SPECIFIC 1,2,3,4 → 4 个项目   （修复前：0 个）
analyst  SPECIFIC 1,2     → 2 个项目
viewer   SPECIFIC 1       → 1 个项目
```

越权防护仍有效（analyst 访问项目 3、4 的影像接口返回 **403**）。

### 注意

- 改了角色的可见项目，**该角色下所有用户下次请求即生效**（不需要重新登录），
  但左侧项目下拉列表在登录时加载，需要刷新页面才看到新项目。
- 「指定项目」不勾任何项目 = 该角色看不到任何项目，界面上会拦住，接口层也会退化为「只看个人成员」。
