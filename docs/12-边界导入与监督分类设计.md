## 一、背景与目标

### 1.1 现状的两个短板

**短板一：AOI 只能手圈**

客户手里的矿山边界通常是 SHP / KML / 坐标表，现在只能照着图手动描一遍。问题有三：
一是慢且不准（几百个拐点的矿权边界根本描不出来）；
二是引入人为误差（描歪几十米，面积和越界判定全跟着错）；
三是画法不稳定（同一个人两次描的顶点不同，区域指纹就变了，时序匹配会失败）。

**短板二：精度答不出来**

当前用指数阈值法（亮度分层 + 形态过滤），能出图、能算面积，但**没法回答"准确率多少"**。
这是客户必问的第一个问题，也是实施方案表 7 的硬指标（IoU / Precision / Recall / F1 / 混淆矩阵）。
监督分类能补上这块：选样本 → 训练 → 分类 → 出混淆矩阵与 Kappa。

### 1.2 目标

1. 支持导入外部边界文件，与手圈 AOI 走**同一套数据结构**，后续流程完全复用
2. 导入的矿权边界可直接作为**越界检测基准**（B5 当前因缺数据而不可用）
3. 新增监督分类模式，输出**可量化的精度指标**（总体精度 OA、Kappa、各类 PA/UA、混淆矩阵）
4. 监督分类结果复用现有链路（矢量化 → 入库 → 时序 → 风险 → 报告），上层不改

### 1.3 非目标（明确不做）

- 不做深度学习语义分割（Mask2Former 需 GPU + 大规模标注，另立阶段）
- 不做亚米级影像的精细边界提取（数据不具备）
- 不做在线编辑 SHP 属性表

## 二、总体设计

两个能力不是并列的，是**咬合**的：

```
客户给边界文件（SHP / KML / GeoJSON / 坐标表）
        │
        ▼
   ① 边界导入 ──► 统一 AOI 结构（外环 + 内洞 + 类型标记）
        │                    │
        │                    ├──► 查询影像 / 监督分类的分析范围
        │                    └──► 越界检测的矿权基准（B5）
        ▼
   ② 监督分类（选样本 → 训练 → 分类 → 精度评价 → 规则修正）
        │
        ▼
   矢量化 → extractions 表 → 时序分析 / 六维风险 / 报告
```

**关键设计原则**：边界导入产出的是"标准 AOI"，监督分类消费的是"标准 AOI"，两者不互相依赖。
所以边界导入可以独立上线（半天到一天就有价值），监督分类后做。

## 三、能力一：边界导入

### 3.1 支持格式与优先级

| 格式 | 优先级 | 说明 |
|---|---|---|
| **SHP（zip 包）** | P0 | 客户最常见。必须支持打包上传，避免"只发了 .shp"的沟通成本 |
| **SHP（多文件选择）** | P0 | 允许一次选中 .shp/.shx/.dbf/.prj |
| **GeoJSON** | P0 | 前端零依赖可直接读，也能承接 QGIS 导出 |
| **KML / KMZ** | P1 | 谷歌地球导出常见，用 DOMParser 解析 |
| **拐点坐标表（CSV/Excel）** | P2 | 外业给的 X/Y 列表，需用户指定坐标系与顺序 |

### 3.2 坐标系处理（最容易出事的一环）

| 源坐标系 | 处理方式 |
|---|---|
| 有 `.prj` 且是标准 EPSG（如 CGCS2000 3 度带 EPSG:4547） | 自动识别并转换 |
| 有 `.prj` 但含 WKT 自定义参数 | 用 WKT 直接构造 CRS 转换 |
| **无 `.prj`** | **拒绝导入**，提示用户手动指定坐标系（不允许猜） |
| 地方独立坐标系 | 提示"无法自动识别"，需用户提供转换参数（四参数/七参数） |
| 已是 WGS84（EPSG:4326） | 直接使用 |

**技术选型（受现有环境限制）**：
`requirements.txt` 已明确"不要装 pyproj"（Python 3.13 + Windows 无预编译轮子）。
所以坐标转换统一走 **rasterio 自带的 CRS / warp**（`rasterio.crs.CRS` + `rasterio.warp.transform_geom`），
与 `sentinel.py` 现有做法一致，不引入新依赖。

### 3.3 导入流程（六步）

1. **接收文件**：zip 包直接解，多文件按扩展名归组（同名的 .shp/.shx/.dbf/.prj 视为一套）
2. **读几何**：`pyshp`（纯 Python，无编译依赖）读 .shp + .dbf；GeoJSON/KML 直接解析
3. **读坐标系**：.prj 文件内容为 WKT → `CRS.from_wkt()`；缺失则报错
4. **重投影**：源 CRS → EPSG:4326（经纬度），保留原始坐标副本用于面积校核
5. **几何规整**：
   - 修复自相交（`shapely.make_valid`）
   - 去除重复点、闭合环首尾
   - 保留内洞（inner ring）
   - 剔除面积过小的碎块（< 0.01 ha，多为数字化噪音）
6. **落库 + 返回**：写入 `aoi_boundary` 表，返回可选列表让用户确认

### 3.4 多要素处理策略

一个 shp 常含多个矿权区块，必须让用户明确选择：

| 策略 | 适用 | 实现 |
|---|---|---|
| **选一个** | 客户只想分析某个采区 | 列出属性表关键字段（名称/编号）供选择 |
| **合并成一个** | 多个相邻区块属同一矿权 | `shapely.ops.unary_union` |
| **拆成多个区域** | 需要分别监测各采区 | 逐个写入 `aoi_boundary`，各自独立时序 |

默认建议"选一个"，因为合并后面积与时序口径会变得难以解释。

### 3.5 AOI 统一数据结构

无论来自手圈、SHP 还是复用历史记录，统一为：

```json
{
  "type": "aoi",
  "outer": [[lng, lat], ...],          // 外环，必填
  "holes": [[[lng, lat], ...], ...],    // 内洞，可空（矿权内的保护区）
  "source": "SHAPEFILE",                // MANUAL | SHAPEFILE | GEOJSON | KML | COORDS | REUSE
  "sourceRef": "矿权边界.shp#FID=3",     // 来源可追溯
  "crsOriginal": "EPSG:4547",           // 原始坐标系（供复核）
  "areaHa": 630.07,                     // 按椭球面积算，非投影面积
  "boundaryType": "PERMIT"              // PERMIT 矿权 | DISTURBANCE 扰动 | ECO 生态红线
}
```

**`boundaryType` 是红线要求**：方案里明确"矿权/项目范围 ≠ 实际扰动边界"，导入时必须让用户选类型，
不能统统叫"边界"。越界检测只认 `PERMIT` 类型的边界。

### 3.6 校验规则（导入时立刻拦住的问题）

| 校验项 | 规则 | 处理 |
|---|---|---|
| 顶点数 | ≥ 3 且闭合 | 报错 |
| 面积 | 0.01 ha ~ 10000 ha | 超出提示"疑似坐标系错误" |
| 自相交 | shapely `is_valid` | 自动修复，修不好则报错 |
| 经纬度范围 | 经度 -180~180、纬度 -90~90 | 超出必然坐标系没转（报错） |
| 与研究区距离 | 与项目中心距离 > 100 km | 警告"可能导错了文件" |
| 顶点数上限 | ≤ 50000（前端渲染性能） | 超出则简化（`simplify`，容差 1e-5°） |

### 3.7 界面设计

放在**遥感提取页的 AOI 区**，与手圈并列：

```
┌─ AOI 圈选 ────────────────────────────┐
│  [手圈]  [导入边界 ▾]  [复用上次]  [清除] │
│                                        │
│  ┌ 导入边界（抽屉）──────────────────┐  │
│  │ 拖入 zip / 选择文件                │  │
│  │ 边界类型：◉矿权  ○实际扰动  ○生态红线│  │
│  │ ────────────────────────────────  │  │
│  │ 解析结果：                        │  │
│  │  ✓ 坐标系 EPSG:4547 → WGS84      │  │
│  │  ✓ 3 个要素，选择要用的：         │  │
│  │    ○ 一采区 125.3 ha             │  │
│  │    ● 二采区 630.1 ha  ← 已选     │  │
│  │    ○ 合并全部 755.4 ha           │  │
```

导入成功后：地图上画出边界、`aoi.value` 直接替换、后续"查询影像"「地形分析」「提取」全部照常。

### 3.8 坑点清单

| # | 坑 | 后果 | 对策 |
|---|---|---|---|
| 1 | 客户只发单个 .shp | 无法解析 | 前端明确提示"需要 .shx/.dbf"，鼓励发 zip |
| 2 | .prj 缺失 | 点位偏移几百米~几公里 | 拒绝导入，要求指定坐标系 |
| 3 | 地方独立坐标系 | 偏移，且无法自动转换 | 要求客户提供转换参数，或提供已知控制点 |
| 4 | .dbf 中文乱码 | 要素名显示为问号 | 按 GBK/UTF-8 双解码尝试，失败则用 FID 命名 |
| 5 | 多环多洞 | 面积算大、越界判定错 | 保留 holes，面积用 `polygon.area`（自动扣洞） |
| 6 | 顶点过密（>5 万） | 前端渲染卡死 | 导入时简化，保留原始文件供下载 |
| 7 | 椭球面积 vs 投影面积 | 与客户台账对不上 | 同时给出两个值，标注口径 |

## 四、能力二：监督分类

### 4.1 双模式定位

不推翻现有阈值法，做成两个模式并存：

| | 快速模式（现有） | 精细模式（新增） |
|---|---|---|
| 输入 | 只圈 AOI | AOI + 样本点 |
| 原理 | 单指数/亮度阈值 | 多波段 + 多指数训练分类器 |
| 耗时 | 秒级 | 10–30 秒 |
| 精度 | 60–75%（经验值） | 75–90% |
| 精度指标 | 无 | OA / Kappa / PA / UA / 混淆矩阵 |
| 用途 | 演示、粗看、大批量 | 正式成果、客户质询、报告 |

### 4.2 完整流程（九步）

```
1. 圈 AOI（手圈或导入 SHP）
2. 加载影像（六波段：B02 B03 B04 B08 B11 B12）
3. 选训练样本（每类 20–50 点）
      └─ 图上点选 → 经纬度 → 反查该像元六波段值 → 存入样本库
4. 特征构造（6 波段 + 5 指数 + 2 地形 = 13 维）
5. 训练/验证划分（分层抽样 7:3）
6. 训练分类器（随机森林）
7. 全图逐像元分类
8. 精度评价（用留出的验证集，不是训练集）
9. 规则修正 + 后处理 → 矢量化 → 入库
```

### 4.3 样本设计（决定精度天花板）

| 要求 | 具体标准 | 原因 |
|---|---|---|
| 每类样本数 | ≥ 20，建议 30–50 | 少于 20 时类别协方差估计不稳 |
| 空间分布 | 分散在图内 ≥ 3 个区域 | 全挤一处 → 只能学到局部特征，外推失效 |
| 类内变异 | 覆盖该类不同形态 | 植被需含林地/灌草/稀疏；排土场需含新旧堆体 |
| 避开混合像元 | 距类边界 ≥ 2 像元（20 m） | 10m 影像边缘是光谱混合区，标签本身就模糊 |
| 训练/验证分离 | 7:3 分层抽样，互相独立 | 用训练集自评会让精度虚高 10–20 个百分点 |
| 样本纯净度 | 剔除同类中的光谱离群点 | 选错点会直接污染该类中心 |

**样本库是资产**：样本落库后可跨期复用（同一矿区下期直接用），将来升级深度学习时可直接当标签。

### 4.4 特征设计

| 特征组 | 具体 | 维度 | 用途 |
|---|---|---|---|
| 原始波段 | B02 蓝、B03 绿、B04 红、B08 近红、B11 短波红外1、B12 短波红外2 | 6 | 基础光谱信息 |
| 指数 | NDVI、NDWI、NDBI、NDMI、BSI | 5 | 增强类间可分性（指数是比值，抗光照差异） |
| 地形 | 高程、坡度（来自 DEM，10m） | 2 | 区分采坑（低洼）与排土场（堆高） |

**必须处理的分辨率对齐问题**：
Sentinel-2 的 B02/B03/B04/B08 是 **10m**，B11/B12 是 **20m**。
若直接把 10m 与 20m 像元当同一网格拼成特征矩阵，就是**把 4 个像元的光谱硬塞给 1 个像元**，特征错位。
正确做法：统一重采样到 10m 网格（双线性重采样 20m → 10m），所有特征在同一网格上对齐。
现有 `sentinel.clip_aoi` 已做尺寸对齐，实施时需确认是"按索引 resize"还是"按地理坐标重采样"——后者才正确。

### 4.5 分类器选型

| 方案 | 依赖 | 优点 | 缺点 | 采用 |
|---|---|---|---|---|
| **随机森林** | scikit-learn | 抗噪声、不需正态假设、给特征重要性、小样本稳 | 需装 sklearn + scipy | ✅ 首选 |
| 最大似然 | numpy 即可 | 经典、无新依赖、可解释 | 要求正态分布，样本少时协方差矩阵奇异 | 备选（仅在 sklearn 不可用时） |
| SVM | scikit-learn | 小样本友好 | 参数敏感、核函数调参 | 备选 |

**环境依赖已验证（2026-10-21 实测）**：

```

scipy        1.18.1  ✅ cp313 wheel（36.6MB）
pyshp        3.1.6   ✅ 纯 Python
```

安装命令（`--only-binary :all:` 强制走预编译轮子，避免源码编译失败）：
```

```

⚠️ **副作用必须记录**：安装 sklearn 时 numpy 被从 `2.2.6` 升级到 `2.5.4`。
已实测回归通过：rasterio 1.4.3、shapely 2.2.0、tifffile、httpx 均正常，
`sentinel` / `dem` / `risk` / `ecology` / `report` 五模块全部加载成功、矢量化正常。
但 `requirements.txt` 里写的是 `numpy==2.2.6`，实施时需**同步更新为实际版本**，
否则下次重建虚拟环境会因版本冲突再次触发升级。

最小冒烟结果（4 类 × 40 样本 × 13 特征，200 棵树）：
`OA 1.000 / Kappa 1.000 / OOB 0.991`，混淆矩阵与特征重要性输出正常，耗时 1 秒内。

随机森林推荐参数：
```
n_estimators=200, max_depth=None, min_samples_leaf=2,
class_weight='balanced',      # 类别不平衡（采坑面积远小于植被）时必须
oob_score=True                # 自带袋外精度估计，可与验证集交叉核对
```

### 4.6 精度评价（这是本能力的核心产出）

必须输出的四组指标：

| 指标 | 计算 | 判读 |
|---|---|---|
| **总体精度 OA** | 正确像元 / 总验证像元 | 总体正确率，单看会掩盖小类失效 |
| **Kappa 系数** | (Po − Pe) / (1 − Pe) | 扣除随机一致性后的真实一致性，>0.8 优、0.6–0.8 良 |
| **生产者精度 PA** | 该类正确 / 该类真实总数 | 漏分率（1−PA），反映"漏了多少" |
| **用户精度 UA** | 该类正确 / 该类被分为该类的总数 | 错分率（1−UA），反映"判成它的有多少是错的" |
| 混淆矩阵 | 类别 × 类别 | 看错分流向（如"裸地→采坑"多少） |

**必须同时给出样本点数与验证策略**，否则精度数字不可信（客户会问"你多少样本、怎么验的"）。

### 4.7 规则修正（NDVI / NDWI 后处理）

原则：**限制性修正，不是无条件覆盖**。阴影的 NDWI 也可能为正，一刀切会把阴影变成水体，精度不升反降。

| 修正规则 | 触发条件（全部满足） | 目标类别 | 说明 |
|---|---|---|---|
| 水体修正 | `NDWI > 0.2` **且** `坡度 < 5°` **且** `非阴影` | WATER | 坡度约束排除山坡阴影；阴影判定用坡度坡向与太阳方位夹角 |
| 植被修正 | `NDVI > 0.35` **且** `非云边缘` | VEGETATION | 高 NDVI 被分为裸地/采坑的，改为植被 |
| 裸地纠偏 | `NDVI < 0.15` **且** `NDWI < 0` **且** `亮度 > 0.15` | BARE | 把误判为水体的裸地拉回 |
| 采坑约束 | 必在 `disturbance` 范围内 | PIT | 采坑不可能出现在植被区 |

**修正前后都要出精度对比**，让客户看到修正是提升还是帮倒忙。若修正后 OA 下降，应默认关闭并记录原因。

### 4.8 后处理

| 步骤 | 参数 | 目的 |
|---|---|---|
| 形态学开运算 | 3×3 核，1–2 次 | 去掉孤立碎斑（椒盐噪声） |
| 形态学闭运算 | 3×3 核，1 次 | 补小洞（分类图内部的漏分像元） |
| 最小图斑 MMU | 20 像元（约 0.2 ha @10m） | 小于此面积的斑块并入邻域多数类 |

> 若无 scipy：形态学用 numpy 手写 3×3 邻域计数实现（约 20 行），或先不做，靠 MMU 过滤。

### 4.10 坑点清单

| # | 坑 | 后果 | 对策 |
|---|---|---|---|
| 1 | 10m 与 20m 波段未对齐 | 特征错位，分类全错 | 统一重采样到 10m 网格再拼特征 |

| 8 | NDVI 修正无条件覆盖 | 精度不升反降 | 限制性条件 + 修正前后精度对比 |

## 七、算法实现要点（Python）

### 7.1 按坐标取光谱

```python
# 已知裁剪窗口的 transform（rasterio Affine）与 CRS
col, row = ~transform * (lng, lat)      # 经纬度 → 像元行列（若 CRS 非 4326 需先转）
bands = {name: arr[row, col] for name, arr in band_arrays.items()}
```
注意：`transform` 是**影像投影坐标系**（如 UTM）下的变换，经纬度须先转到该 CRS 才能取行列。
现有 `clip_aoi` 返回了 `meta["B04"]["transform"]` 与 `crs`，可直接复用。

### 7.2 特征矩阵

```
X = np.column_stack([b02, b03, b04, b08, b11, b12,   # 6 波段（统一到 10m）
                     ndvi, ndwi, ndbi, ndmi, bsi,     # 5 指数
                     elev, slope])                    # 2 地形
y = labels   # 来自样本点
```

### 7.3 训练与评价

```
分层抽样 7:3 划分 → 训练 → 预测验证集 → 混淆矩阵 → OA/Kappa/PA/UA
```

### 7.4 全图分类与后处理

```
逐像元预测（sklearn 直接 predict 二维展平）→ reshape 回栅格
→ 形态学开闭 → MMU 过滤 → rasterio.features.shapes 矢量化 → GeoJSON
```

## 十二、口径红线（必须写进产品与报告）

1. 监督分类精度只在**给定样本与验证策略**下成立，不得脱离条件宣称"准确率 90%"
2. 报告必须同时给出：样本数、每类样本分布、训练/验证划分比例、混淆矩阵
3. 10m 分辨率**不适用于台阶坡面角、坑深、体积**，分类结果只到"采坑整体"尺度
4. 「规则修正」是后处理启发式规则，不是独立验证，**不得把修正后精度当作模型能力**
5. 导入的边界若为"矿权范围"，不得表述为"实际扰动边界"；越界判定须注明双方来源与日期
6. 分类结果仍属「潜在水土流失风险筛查」与「潜在安全风险筛查」的证据，不构成实测结论
