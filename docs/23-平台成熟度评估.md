# 平台成熟度评估报告

> 评估日期：2026-10-22
> 评估对象：智慧矿山平台（遥感解译 + 变化监测 + 安全生态评估 + 三维 WebGIS）
> 评估方法：代码规模统计、工程质量核查、功能覆盖比对、实际接口验证
> 说明：本评估基于仓库当前状态，不含未提交的本地改动

---

## 一、总体结论

### 定位：**L3 可交付原型（Demo-Ready Prototype）**，处在 L3 偏成熟阶段

按业界常用的产品成熟度分级：

| 等级 | 定义 | 本平台 |
|---|---|---|
| L1 PoC | 只有核心算法能跑通 | 已远超 |
| L2 Demo | 能串起一条演示链路 | 已远超 |
| **L3 可交付原型** | **多条业务链路完整、可给他人试用、有已知限制清单** | **← 当前** |
| L4 Beta | 有测试/监控/部署方案，小范围真实使用 | 未达 |
| L5 生产 | SLA、容灾、审计、性能保障 | 未达 |

### 一句话判断

**功能广度已经超过多数行业 Demo，专业口径把关是最大亮点；短板全部集中在工程可靠性（测试、部署、可维护性），而不在"功能有没有"。**

### 分场景评分

| 用途 | 评分 | 判断 |
|---|---|---|
| 给客户做技术演示 | **8.5 / 10** | 很强。30 个页面、103 个接口、核心链路有真数据，能撑 1 小时不重复 |
| 让客户小范围试用（Alpha） | **6.5 / 10** | 能用，但会碰到超时、大文件、首次拉景慢等体验问题 |
| 交付客户正式上线 | **4 / 10** | 差距明显：无测试、无监控、部署靠手工、单机无容灾 |

## 四、真正的优势（拿单时该强调的）

1. **不是假 Demo**
   解译走真实 Sentinel-2 COG 数据与指数计算，安全评估带 AHP 一致性检验，
   生态指数 PC1 载荷符号正确——这些细节懂行的客户一眼能看出区别。

2. **口径红线守得死**
   主动声明「10m 分辨率是 B 级证据」「不能报实测侵蚀量」「持续复绿不等于修复成功」。
   面向国企/上市公司，这种克制比吹嘘更能建立信任。

3. **功能广度压倒性**
   30 个页面覆盖：数据准备 → 解译 → 融合 → 监测 → 空间分析 → 安全生态评估 → 报告输出，
   客户提的绝大多数需求都能当场点开演示，而不是"这个下期做"。

4. **项目级数据隔离是真的**
   16 张表按 project_id 隔离，三层权限控制，实测越权返回 403。
   客户会问"我们的数据会不会被别的项目看到"，这是能当场验证的答案。

## 五、关键差距（按"影响拿单"排序）

### P0：演示现场会踩到

| 问题 | 影响 | 建议 |
|---|---|---|
| 首次在线拉景 1~10 分钟 | 演示时点"提取"后干等，客户会走神 | 提前跑预热 tile 缓存；准备离线演示包 |
| 大文件上传受免费带宽限制 | 穿透演示时传几百 MB 影像会超时 | 提前上传好，现场不演示上传 |
| 单点故障：4 个服务任一挂了全站不可用 | 演示前必须逐个确认 | 加「依赖健康面板」（已有 HealthView）并演示前检查 |

### P1：客户试用几次后会问

| 问题 | 影响 | 建议 |
|---|---|---|
| 0 单元测试 | 改一处可能悄悄弄坏另一处，交付后不敢改 | 至少补接口冒烟测试 |
| 无 API 文档 | 客户技术团队要对接时无从下手 | 加 springdoc，成本很低 |
| 部署靠手工 | 客户问"我们自己怎么部署"时答不上 | 把 docker-compose 真正跑通一次 |
| 无监控告警 | 出问题只能等用户反馈 | 至少加日志文件 + 简单告警 |

### P2：长期交付才暴露

- 超大文件待拆分（2141 行 Vue、1488 行 Python）
- 权限点粒度粗（`action:extract-manage` 一个点管一堆操作）
- 无 CI/CD，靠手工 build
- 无数据备份与恢复演练

## 六、与需求文档的贴合度（更新）

`docs/07` 在 10-20 评估时给出综合 **78%**，主要缺口是：
- 在线提取只开放 5 类地物 ❌ **已补**（现 7 类全开）
- 缺精度评估（Kappa/混淆矩阵）❌ **已补**（监督分类已输出 用户精度/生产者精度/F1）
- 缺侵蚀风险、指标口径细节 ⚠️ 部分补（RSEI + AHP 安全指数）

**当前估计贴合度约 85%**。剩余主要缺口是专业深度（深度学习分割模型、亚米级影像）而非功能有无。

## 七、走向下一级的路径

### 想到 L4（客户小范围试用），必须补三件

1. **接口冒烟测试**（覆盖 103 个端点的主路径，能在 5 分钟内跑完）
2. **docker-compose 跑通**（一键起 MySQL + 后端 + inference + 前端，附部署文档）
3. **日志落文件 + 简单告警**（至少能事后查"昨天那次失败为什么"）

预计工作量：**3~5 个工作日**，不涉及新功能，纯工程加固。

### 想到 L5（正式交付），还需

- 数据库迁移用 Flyway（现在是 `ddl-auto=update`，生产环境危险）
- 引入对象存储（MinIO）替代本地文件路径
- Redis 缓存 + 限流
- APM 与告警（Prometheus + Grafana 或云监控）
- 灾备与备份策略
- 等保合规（若客户是国企，等保二级起步）

预计：**4~8 周**（含联调与验收文档）。

## 八、给决策的建议

**如果目标是 12 月给赣锋演示拿单**：当前状态**够用，甚至超预期**。
精力不要花在加功能上，全部投到「演示保险」：
- 离线演示数据包预置到位
- 演示脚本走一遍计时（控制在 20 分钟内）
- 准备 2~3 个客户可能追问的专业问题的答案（精度多少？口径是什么？）

**如果演示后客户要试用（POC）**：先花 3~5 天补 L4 那三件，
否则客户试用时遇到的每个小问题都会被放大成"这系统不稳定"。

**如果客户直接谈采购交付**：需要正视 4~8 周的工程化差距，
不要在商务谈判中承诺"下周就能上线"。
