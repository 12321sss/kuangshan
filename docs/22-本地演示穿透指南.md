# 本地演示：把平台穿透给外部试用

> 场景：不给客户部署服务器，直接把你本机跑着的平台映射到公网，让对方打开链接就能用完整功能。
> 日期：2026-10-22

---

## 一、核心结论：只穿透 **5173** 一个端口

不需要把后端 8080、解译服务 8010 也暴露出去。原因是前端 dev server 已经做了解译代理：

```
外部用户浏览器
      │  https://xxx.cpolar.top
      ▼
你的本机 Vite (5173)  ──/api──────► Java 后端 (127.0.0.1:8080)
      │                ──/sentinel──► inference (127.0.0.1:8010)
      │
      └─ 静态页面 / Cesium 资源
```

前端所有请求都用**相对路径**（`baseURL: '/api'`、`'/sentinel'`），
浏览器只会向穿透域名发请求，由 Vite 在本机内部转给 8080 / 8010。

**好处**：
- 只开一个洞，攻击面最小
- 后端与 inference 不需要配置 CORS、也不需要公网证书
- 解译服务回调 Java 走的是 `http://localhost:8080/...`（本机内部），不受穿透影响

---

## 二、启动前：开「演示模式」

穿透域名的 Host 头是随机的，Vite 5+ 会因 DNS rebinding 防护直接拦掉。所以提供了开关：

```bash
cd frontend

# Git Bash / WSL
TUNNEL=1 npm run dev

# PowerShell
$env:TUNNEL=1; npm run dev

# CMD
set TUNNEL=1 && npm run dev
```

开启后会自动做两件事：

1. `allowedHosts: true` —— 任何穿透域名都能访问，不用每次改白名单
2. `hmr: { protocol: 'wss', clientPort: 443 }` —— https 穿透下热更新的 ws 才能连上

> 不设 `TUNNEL=1` 时保持本地开发行为（只允许 localhost / IP + 白名单域名）。
> **改完 vite.config.ts 必须重启 dev server**，它不热更新。

## 三、穿透工具怎么选

| 工具 | 要注册 | 免费额度 | 国内速度 | 域名形态 | 适用 |
|---|---|---|---|---|---|
| **cpolar** | 是（手机号） | 免费版 1 条隧道，带宽/流量有限 | **好** | `xxx.cpolar.top` | **推荐给客户演示** |
| **natapp** | 是（需实名） | 1 条免费隧道 | 好 | `xxx.natappfree.cc` | 备选，实名略麻烦 |
| **ngrok** | 是 | 1 条 | 差（海外节点） | `xxx.ngrok-free.app` | 自己临时用 |
| **cloudflared** | **否** | 无限制 | 一般（海外） | `xxx.trycloudflare.com` | 免注册，但国内访问不稳 |
| frp | 需要自己有公网服务器 | 看服务器 | 取决于服务器 | 自定义域名 | 长期方案 |

> 免费版通常有**带宽（1~5 Mbps）和流量**限制。演示影像上传会很慢，
> 这一点在第四节的检查清单里有应对办法。

### cpolar 操作步骤（推荐）

1. 打开 https://www.cpolar.com 注册（手机号即可）
2. 下载 Windows 客户端并安装
3. 登录客户端 → 首页复制 **authtoken**
4. 命令行执行一次（把 token 换成你的）：
   ```
   cpolar authtoken 你的一串token
   ```
5. 开隧道，指向本机 5173：
   ```
   cpolar http 5173
   ```
6. 终端会打印一个公网地址，形如：
   ```
   Forwarding  https://xxxxxxxx.r3.cpolar.top -> http://localhost:5173
   ```
   这个地址直接发给客户即可

**注意**：免费版每次重启隧道**域名会变**，发给客户前先确认当前地址。

### cloudflared 快速隧道（免注册，备用）

```bash
cloudflared tunnel --url http://127.0.0.1:5173
```
终端会打印 `https://xxxx.trycloudflare.com`。不需要账号，但国内访问速度不稳定。

## 四、演示前检查清单

按顺序过一遍，避免现场翻车：

### 1. 四服务全部在线

```bash
# 注意：本机访问必须加 --noproxy，否则系统代理会让 localhost 返回 502
curl --noproxy '*' http://localhost:8080/actuator/health
curl --noproxy '*' http://127.0.0.1:8010/health
curl --noproxy '*' -o /dev/null -w "%{http_code}" http://127.0.0.1:5173/
```
MySQL 由 `start.bat` 或手动启动，四个都要是 UP / 200。

### 2. 准备演示账号

对外演示**不要让客户用 admin**。建议：

| 账号 | 角色 | 用途 |
|---|---|---|
| `demo` | ANALYST | 给客户操作：能圈 AOI、提取、做安全评估，不能改用户与权限 |

在「平台管理 → 用户管理」新建，密码设简单点（如 `demo1234`），演示完改掉或禁用。

### 3. 准备演示数据（重要）

免费穿透带宽小，**现场上传几百 MB 的 GeoTIFF 基本会超时**。所以提前做好：

- 影像库里**预先上传** 2~3 期影像（覆盖多个年份，便于演示时序）
- 边界管理里**预先导入**矿权边界
- 至少跑过一次解译，让「时序与构成」有数据
- 用「一键载入演示数据」准备好离线包（断网也能演示）

### 4. 清掉测试数据

删掉「测试矿区A」这类临时项目，避免客户看到杂乱列表。

### 5. 提前用手机 4G 试一次

不要只在自己电脑上验证——用手机流量打开穿透链接，
确认 1) 能登录 2) 地图能加载 3) 点几个页面不报错。

## 五、已知限制（演示时要避开）

| 限制 | 表现 | 应对 |
|---|---|---|
| **带宽** | 免费版 1~5 Mbps，Cesium 三维底图加载慢 | 演示前把地图飞到目标矿区，减少瓦片加载 |
| **大文件上传** | 影像上传中途失败 / 卡住 | 提前上传，现场不要演示上传大文件 |
| **在线拉景慢** | AWS STAC 首次拉 Sentinel-2 需 1~10 分钟 | 提前跑一次预热 tile 缓存，或用离线演示包 |
| **域名会变** | 免费版重启隧道换域名 | 演示当天重启隧道后重新确认地址 |
| **穿透断连** | 长时间空闲会被服务端断开 | 演示期间保持页面活跃；备一个第二方案（如 natapp 备用隧道） |
| **热更新** | 演示中改代码不会自动刷新 | `TUNNEL=1` 模式下已配 wss，仍失败就手动 Ctrl+F5 |

## 六、安全提醒（务必看）

1. **穿透链接等于把你本机端口暴露到公网**。任何人拿到链接都能访问登录页，
   所以：演示账号权限给最小、密码别用 admin 的、**演示结束立刻关掉隧道**（Ctrl+C）。

2. **不要用 `host: true` + 全放开 allowedHosts 长期跑**。DNS rebinding 防护是有意义的，
   平时本地开发保持默认白名单，只在演示时开 `TUNNEL=1`。

3. 别在演示环境放真实客户数据。演示完清理上传的影像与解译结果。

---

## 七、要更稳的方案

如果演示很重要、不能出岔子，建议不要用 dev server + 免费穿透，改为：

1. `npm run build` 出静态产物
2. 用 Nginx 托管静态文件 + 反向代理 `/api`、`/sentinel` 到本机 8080/8010
3. 再对 Nginx 的 80 端口做穿透

好处：没有 Vite 的 HMR / allowedHosts / 文件监听开销，静态资源 gzip 后体积小得多，
弱网下加载明显更快。缺点是要多配一个 Nginx。

这套方案需要时可以让 AI 帮你写配置。
