# 两台电脑同步指南

> 仓库：https://github.com/12321sss/kuangshan.git（私有）
> 仓库里放什么：**源码 + 文档 + 配置模板**，共 160 个文件、约 2.4 MB
> 仓库里不放什么：**依赖、构建产物、数据库、影像缓存**（都可重建，体积 737 MB）

---

## 一、哪些东西会同步、哪些不会

| 内容 | 是否同步 | 说明 |
|---|---|---|
| frontend / backend-java / inference 源码 | ✅ 同步 | 核心 |
| docs、需求文档、技术大纲 | ✅ 同步 | |
| `.workbuddy/memory`（项目记忆） | ✅ 同步 | 换电脑后能接上之前的决策上下文 |
| `.gitignore` / `.gitattributes` | ✅ 同步 | 保证两台机器行为一致 |
| `node_modules`（352 MB） | ❌ 不同步 | 每台机器 `npm install` |
| `inference/.venv`（262 MB） | ❌ 不同步 | 每台机器建 venv 装依赖 |
| `backend-java/target`（54 MB） | ❌ 不同步 | 每台机器 `mvn package` |
| `inference/.cache`（70 MB） | ❌ 不同步 | 首次提取时自动重新下载瓦片 |
| **MySQL 数据库里的数据** | ❌ **不同步** | 见下方「数据库怎么同步」 |

## 二、第二台电脑第一次拉取

### 情况 A：第二台还没有这个项目

```bash
cd E:\LYY
git clone https://github.com/12321sss/kuangshan.git 赣锋锂电遥感解译平台
cd 赣锋锂电遥感解译平台
```

clone 时如果要求登录：GitHub 已不支持密码，需要用 **Personal Access Token**（Settings → Developer settings → Personal access tokens → Tokens(classic) → 勾 `repo` 权限），粘贴 token 当密码。

### 情况 B：第二台已经有这个目录（只是没 git）

如果第二台已经有同名文件夹且代码较旧，不要直接 clone 覆盖，用下面方式接管：

```bash
cd E:\LYY\赣锋锂电遥感解译平台
git init -b main
git remote add origin https://github.com/12321sss/kuangshan.git
# 把本地旧版备份掉，避免覆盖冲突
git fetch origin
git reset --hard origin/main
```
> ⚠️ `reset --hard` 会覆盖本地未提交的改动。如果第二台有本地才有的改动，先手动复制出来。

### 拉完后重建环境（必须做）

```bash
# 1. 前端依赖
cd frontend && npm install && cd ..

# 2. 解译服务 Python 环境
cd inference
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
cd ..

# 3. 后端编译
cd backend-java
mvn -s ../deploy/maven-settings.xml -DskipTests package
cd ..
```

## 三、日常同步流程（两台都用这套）

### 改完代码要传走的那台

```bash
git status                    # 先看改了什么
git add -A
git commit -m "feat: 新增坡度变化率指标"
git push
```

### 要拿到最新代码的那台

```bash
git status                    # 确认自己没未提交的改动
git pull
```

**养成习惯：动手改代码前先 `git pull`**，能避免 80% 的冲突。

## 四、数据库怎么同步（重要）

代码同步了，但**数据不会自动同步**——MySQL 数据在每台机器本地。

三种做法，按需要选：

### 做法 1：不同步数据（最简单，推荐）

第二台建空库自己造测试数据。适合"代码为主、数据无所谓"的情况。

```sql
-- 第二台建库
CREATE DATABASE rs_platform DEFAULT CHARSET utf8mb4;
```
后端启动时 JPA 会自动建表，再跑一次演示数据初始化即可。

### 做法 2：手动导出/导入（偶尔同步一次）

在 A 电脑导出：
```bash
mysqldump -u root -proot --databases rs_platform > backup.sql
```
把这个 `backup.sql` 通过微信/网盘传到 B 电脑，然后：
```bash
mysql -u root -proot < backup.sql
```
> `backup.sql` 已在 `.gitignore` 里（`*.sql` 未排除，但含 `INSERT` 的备份文件体积可能较大，建议走网盘而不是 Git）。

### 做法 3：把数据库也纳入版本管理（不推荐）

数据库文件二进制且经常变动，容易冲突且体积膨胀，不建议。

## 五、两个必须注意的坑

### 1. 换行符

两台都是 Windows，已经用 `.gitattributes` 统一成 LF（`*.bat` 保留 CRLF）。**不要手动改这个文件**，否则会出现"整文件都被修改"的假 diff。

### 2. 如果 A 电脑改了后端配置（如数据库密码）

`backend-java/src/main/resources/application.yml` 会同步过去。如果两台机器 MySQL 密码不同，B 电脑拉下来后要改本地的这一行——但这样又会造成新的 diff。

**正确做法**：把这类机器相关配置挪到环境变量或 `application-local.yml`（已在 `.gitignore` 排除），主配置只保留占位默认值。

## 六、同步状态自查

```bash
git log --oneline -3           # 最近三次提交
git status -sb                 # 是否领先/落后远程
git remote -v                  # 远程地址是否正确
```

`git status -sb` 输出含义：
- `## main...origin/main` → 完全同步
- `## main...origin/main [ahead 2]` → 本地多 2 个提交，要 push
- `## main...origin/main [behind 1]` → 远程多 1 个提交，要 pull
