# S2/S3/S4 真实解译链路实施方案

> 状态：**S2 数据源已验证可行**（2026-10-16 实测），S2 代码/S3/S4 待实现
> 前提：本机无 GPU、无 Docker，Python 3.13（numpy必须 2.x、rasterio 1.5+）

## 一、先明确两条解译路线的分工

用户明确区分，这是架构前提，不要混淆：

| 路线 | 数据来源 | 入口 | 数据流|
| --- | --- | --- | --- |
| **上传遥感图像解译** | 高分影像（GF-2 等商业数据，客户采购） | 用户上传文件 → 影像入库 → **地图上点击影像 → 点「开始提取」** | 文件落盘 + 影像库列表 + GeoTIFF 读取 |
| **在线提取** | 公开数据（Sentinel-2 / Landsat，平台自己拉） | 圈 AOI → 检索场景 → 选景 → 提取 | Copernicus API 检索下载 |

**关键交互（用户明确要求）**：上传影像后**先在地图上显示出来**，再点选开始提取——
不是「上传即提取」。所以必须有独立的**影像库**概念（imagery 表），承载两种来源。

## 二、功能整合：删掉重复的独立任务页

现状三套东西抢同一件事：

- `/api/extractions`（在线提取页，518 行）——有地图、有面积、有双色对比，功能最全，但**造数据**
- `/api/tasks`（任务页，181 行）——只有文字列表，**无地图无结果**，进度是 20秒模拟器
- `/api/analysis`——硬编码数组出图表

**整合决策**：

1. **删除 `TasksView.vue` 独立页面及其菜单项**（用户已确认）
2. **保留 `ExtractView.vue` 骨架**（地图+AOI+对比写得最全，白扔可惜），
   在其上扩展成「解译工作台」，把任务进度概念合并进来
3. **新增 `ImageryView.vue`（影像库）**：上传区+ 场景检索区 + 地图预览 + 「开始提取」按钮
4. `/api/tasks` 降级为**任务流水（供报告与追溯用）**，不再作为独立页面，
   由真实提交提取时自动创建

整合后的主链路：

```
影像库 Imagery（上传高分影像 / 检索Sentinel-2 场景）
    ↓ 地图上点选一景 → 点「开始提取」
解译任务 Task（真实调 inference，算完回调入库）
    ↓
提取结果 Extraction（矢量上图 + 面积/覆盖率）
    ↓
时序对比（同AOI 多期结果叠加）→ 变化分析 → 报告导出(S4)
```

## 三、已验证的事实（不用重新踩坑）

### 3.1 Sentinel-2 可达性 ✅

- 数据源：**Copernicus Data Space**（欧空局官方新门户）
  `https://catalogue.dataspace.copernicus.eu` —— 无需注册即可检索元数据
- 样区实测（江西宁都河源115.2E / 26.3N）：
  - 2023 全年命中 **284 景**
  - 2023 全年云量 <40% 有 4 景，其中 **云量 0.0% / 0.4%** 两景几乎无云，算指数最理想
  - 每景瓦片T50RLQ 完整覆盖样区，整景 666MB
- **QUICKLOOK 预览图可正常下载**（14–27KB JPEG），已目视确认为真实赣南林地影像
- 探测脚本已固化：`inference/sentinel_source.py`

### 3.2 四个必须记住的实现坑（全部实测）

1. **SSL**：Windows 下Python 标准库证书链不含 Copernicus 根证书，
   直连会 SSL 握手中断。必须 `verify=certifi.where()`。
   注意 `requests` 的 `verify` **只接受路径字符串，不接受 SSLContext 对象**。
2. **`$expand` 必须写成重复参数**：`$expand=Attributes&$expand=Assets`。
   写成 `$expand=Attributes,Assets` 服务端直接 400。
   - `Attributes` 不展开 → 云量只在过滤时生效，**无法回显给前端**
   - `Assets` 不展开 → 拿不到 QUICKLOOK 下载入口
3. **`urlencode` 必须加 `quote_via=urllib.parse.quote`**：默认会把空格编成 `+`，
   而 OData 的 `geography'POINT(115.2 26.3)'` 里空格是有效分隔符，编成 `+` 会被拒。
4. **`/Products(id)/Assets` 直接访问404**，资产只能通过 `?$expand=Assets` 拿。

### 3.3 Python 3.13 依赖约束

- `numpy` **必须 2.x**（3.13 无 1.26 预编译轮子，只能源码编译会失败）→ 用 2.2.6
- `rasterio` 必须 1.5+ → 用 1.5.2（自带 GDAL 全套，含 CRS/warp）
- **不要装 `pyproj`**：Windows 无预编译轮子且 3.13 编译失败；
  rasterio 已覆盖其能力（`rasterio.warp` / `rasterio.crs`）

## 四、S2 解译闭环（真实算法）

### 4.1 数据模型新增

```sql
-- 影像库：两种来源统一承载
CREATE TABLE imagery (
  id BIGINT PK AUTO_INCREMENT,
  project_id BIGINT NOT NULL,
  name VARCHAR(128) NOT NULL,
  source VARCHAR(24) NOT NULL,        -- UPLOAD(高分影像) / SENTINEL2 / LANDSAT9
  file_path VARCHAR(512),             -- 上传影像落盘路径（source=UPLOAD 时有值）
  product_id VARCHAR(64),             -- Copernicus 产品 ID（公开数据源时有值）
  acquisition_date DATE NOT NULL,
  cloud_cover DECIMAL(5,2),           -- 上传影像为 NULL
  resolution_m DECIMAL(6,2),         -- 米/像素：GF2=0.8, S2=10
  west/south/east/north DECIMAL(11,7),-- 覆盖范围
  quicklook_path VARCHAR(512),
  status VARCHAR(16) NOT NULL,        -- READY / PROCESSING / FAILED
  created_at DATETIME NOT NULL,
  INDEX idx_project (project_id)
);
```

### 4.2 七类地物的指数法分类（demo 算法，GPU 就位后换 Mask2Former）

只用 Sentinel-2 常用波段即可覆盖七类：

| 地物类 | 判据 | 所需波段 |
| --- | --- | --- |
| 植被 VEGETATION | NDVI = (B08-B04)/(B08+B04) > 0.3 | B04,B08 |
| 水体 WATER | NDWI = (B03-B08)/(B03+B08) > 0.1 | B03,B08 |
| 裸地扰动 BARE | NDBI = (B11-B08)/(B11+B08) > -0.1 且 NDVI < 0.3 | B08,B11 |
| 采坑 PIT | 裸地 + 高程/形态特征（本机无 DEM，先用裸地+纹理近似，标注局限） | B04,B08,B11 |
| 排土场 DUMP | 同采坑（区分需形态，标注局限） | 同上 |
| 尾矿 TAILINGS | 裸地 + 水体邻近 | 同上 |
| 道路设施 ROAD | 线性纹理（NDVI 低 + 亮度高），本机先简化 | B02,B03,B04 |

> **口径红线**：指数法出的是「**潜在水土流失风险筛查**」，不是实测侵蚀量；
> 采坑/排土场/尾矿的形态区分精度有限，必须在报告与界面标注局限。

### 4.3 链路

```
Java: POST /api/extractions {imageryId, aoi[], classType}
  → 调inference: POST /api/v1/inference/submit
      {image_path, algo_type:"INDEX", params:{aoi, class_type}}
  → inference: 读波段 → 算指数 → 阈值分割 → rasterio.features.shapes 矢量化
      → shapely 转 GeoJSON → POST 回调 Java /api/callback/task-complete
  → Java: 结果入库 extractions 表（features_json, area_ha, coverage_pct）
```

**矢量面积计算**：Python 侧用 rasterio 的 `transform` + `shapely.area`，
或在 UTM 投影下算（推荐：`pyproj` 不可用时用 rasterio 自带 warp）。
Java 侧保留现有 `ringAreaHa` 作交叉校验，两者不一致时告警。

## 九、风险

- **整景 666MB 下载**：demo 阶段用 QUICKLOOK + 按波段裁剪；
  真实提取若拉整景会很慢，需要在服务端做 AOI 裁剪后再下载（Copernicus 支持
  `Assets(<id>)/$value` 但裁剪需自建流程，或改用 WMS/WCS 服务端取窗）
- **无 GPU**：指数法是 CPU 可跑的唯一选择，精度有限属预期内
- **采坑/排土场/尾矿形态难分**：本机无DEM/无分割模型，
  demo 阶段需合并呈现并标注局限，别硬撑成七类都很准的样子
