# 分类结果 × 指数结果 叠加分析（融合）设计

> 场景：同一批影像、同一个 AOI，一次监督分类出七类地物，一次指数提取单独提了水体/植被。
> 客户现场常问："你这两套结果对得上吗？""我觉得水体那个提得准，能不能以它为准？"
> 本文设计一套可解释、可出图、可沉淀的叠加分析能力。

---

## 一、要解决的三个真实需求

| 需求 | 用户原话 | 本质 |
|---|---|---|
| **互校** | "分类出来的水体，和指数提的水体，是一回事吗？" | 两种方法的一致性检验 |
| **择优** | "我觉得指数提的水体有用，就叠加上去" | 按类替换/补充：某类以指数为准 |
| **出图** | "后面最好能输出专题图" | 专题图 + 图例 + 口径标注，进汇报/报告 |

---

## 二、能力分三层（由轻到重，可分批实施）

### L1 叠加显示（不改数据，最快见效）

同一 AOI、同一期：
- 分类结果作**面填充**（半透明，按类着色）
- 指数结果作**描边**（同色系深色，虚线）
- 差异模式：三色填充 —— 一致（灰）/ 仅分类（橙）/ 仅指数（蓝）

价值：肉眼就能看出"哪里两套结果打架"。

### L2 差异分析（出统计与待核查点）

对每个「分类类 ↔ 指数类」配对，计算四组面积与一致性指标：

```
A = 分类该类面积
B = 指数该类面积
I = 两者交集（一致）
D_c = 仅分类（A − I）
D_i = 仅指数（B − I）

IoU = I / (A + B − I)                 交并比（一致性，不是精度！）
一致率 = I / A                         以分类为分母
补充率 = D_i / B                       指数比分类多出来的比例
漏提率 = D_c / A                       分类比指数多出来的比例
```

并列出**待核查斑块**：把 D_c / D_i 的连通斑块按面积排序，取前 N（默认 10）个，
给中心坐标 + 面积，供现场核查。结论措辞：

> 水体：分类 12.4 ha，指数 9.8 ha，一致 9.1 ha（IoU 0.72）。
> 有 3 处共 3.3 ha 分类判为水体但指数不支持（多为浅水/阴影），建议现场核实。

### L3 融合产品（生成新结果 + 专题图）

三种策略，都是**按类**生效（不是整幅图一刀切）：

| 策略 | 含义 | 适用 |
|---|---|---|
| **指数优先**（推荐默认） | 指定类用指数结果，其余类保留分类 | 用户明确说"水体以指数为准" |
| **仅保留一致** | 该类只保留两边都认的部分 | 对外汇报要"高置信" |
| **指数补充** | 分类 ∪ 指数（取并集） | 排查分类漏提 |

融合结果落库为**新的解译记录**，`method=FUSION`，`name` 带"融合"字样，
并在 `note/accuracyJson` 里记下：参与融合的记录 id、策略、各类面积变化。

---

## 三、数据前提（必须先补的一处模型改动）

现在 `extractions` 表**没有记录解译方法**，只能靠 `name` 里是否含"监督分类"来猜。
融合要按方法筛数据，必须加字段：

```sql
ALTER TABLE extractions ADD COLUMN method VARCHAR(16) DEFAULT 'INDEX';
-- INDEX    指数阈值法（现有全部记录）
-- SUPERVISED 监督分类
-- FUSION   融合结果
ALTER TABLE extractions ADD COLUMN accuracy_json TEXT NULL;
-- 监督分类时存 OA/Kappa/混淆矩阵；融合时存策略与参与记录 id
```

同时给保存接口加 `method` / `accuracyJson` 两个可选参数（默认 INDEX，兼容旧调用）。

**配对规则**：优先要求 `同一 AOI 指纹 + 同一期（YYYY-MM）`；不满足时给出警告，
允许用户强制继续（跨期叠加本身有风险，必须让用户知情）。

---

## 四、算法实现（Python，`inference/fusion.py`）

两边都是**矢量**，直接几何叠加最准，不必栅格对齐：

```
1) 各自 union（同类多斑块合并），投影到局部米制（复用 risk._to_local_meters）
2) I = A ∩ B；D_c = A − I；D_i = B − I
3) 面积取几何面积（米制），与其它模块口径一致
4) 连通斑块：D_c/D_i 的 Polygon/MultiPolygon 拆开后按面积排序
5) 融合：
   - INDICES_FIRST: final[cls] = B；其余类 = 分类原样
   - INTERSECT_ONLY: final[cls] = I
   - UNION_ADD: final[cls] = A ∪ B
6) 输出：每类的 features（GeoJSON）+ 统计表 + 差异斑块列表
```

专题图栅格化：把融合结果按类着色画成 PNG（无文字），图例由前端合成。

## 五、接口设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/extractions?projectId=&method=` | 列表支持按方法筛（新增参数） |
| POST | `/api/analysis/fusion/compare` | 只做差异分析：入参含分类/指数两边的 features 与配对 |
| POST | `/api/analysis/fusion/merge` | 融合并按策略生成结果（不落库，返回 features + 统计） |
| POST | `/api/extractions/save` | 现有接口，新增 `method` / `accuracyJson` 可选字段 |

入参（compare / merge 共用）：

```json
{
  "projectId": 1,
  "pairs": [{ "classType": "WATER", "strategy": "INDICES_FIRST" }],
  "classified": { "WATER": [Feature...], "VEGETATION": [...] },
  "indices": { "WATER": [Feature...] },
  "period": { "classified": "2026-09", "indices": "2026-09" },
  "options": { "minPatchHa": 0.2, "topPatches": 10, "withImage": true }
}
```

## 六、页面设计（新页 `/fusion`「结果融合」）

三步走，不让用户面对一堆下拉：

**第 1 步 选数据**
- 「分类结果」：列出 `method=SUPERVISED` 的记录，按 AOI 分组、按期排序，选一条（或一次选全部类）
- 「指数结果」：列出 `method=INDEX` 的记录，按同样分组
- 自动提示配对：`同一 AOI ✅ / 同一期 ❌（分类 2026-09，指数 2026-08）`，不匹配时给黄色警告
- 配对表：自动按同类型配对，允许逐行改（比如"植被用指数、其余用分类"）

**第 2 步 看差异**
- 顶部四指标卡：分类面积 / 指数面积 / 一致面积 / IoU
- 中间差异图（三色）+ 图例
- 下方待核查斑块表（类型、面积、中心坐标、可复制）

**第 3 步 出产品**
- 策略选择（按类）：指数优先 / 仅一致 / 指数补充
- 预览融合图 → 「保存为解译记录」（method=FUSION）
- 「导出专题图 PNG」「加入报告」

## 七、专题图怎么做（关键工程决策）

**底图后端出、图例前端合成**：

| 部分 | 谁做 | 原因 |
|---|---|---|
| 分类/差异色块 | 后端 rasterize → PNG | 快、且与栅格口径一致 |
| 标题/图例/比例尺/来源/日期 | 前端 canvas 合成 | 中文字体在后端（尤其 Linux 服务器）不可靠，前端一定有 |

专题图必备要素（少一样都不算正式图件）：

```
标题：宁都河源矿区 2026-09 地物分类-指数融合图
图例：7 类色块 + 差异三色 + 说明（哪类采用指数结果）
比例尺：由 mPerPixel 与图像宽度算出
数据来源：Sentinel-2 L2A（2026-09-27）/ 分辨率 10 m / AOI 面积 xx ha
生成时间 + 平台名
口径声明：潜在风险筛查，非实测；IoU 为方法一致性，不是精度
```

报告插图：`report.py` 里用 PIL 尝试加载系统字体（Windows `msyh.ttc`），
失败则插入无文字图，并在 Word 里用**表格代替图例**（保证任何环境都能出）。

## 八、口径红线

1. **IoU / 一致率 ≠ 精度**：只是两种方法的一致性，不能写"分类精度 72%"。
2. 不一致区域只能说「**建议核查**」，不能断言"分类错了"——指数法同样会误判（阴影）。
3. 融合结果必须标注**构成来源**（哪些类来自指数、哪些来自分类）。
4. 专题图必须带数据源、日期、分辨率、生成时间；否则不可用于对外汇报。
5. 跨期叠加属高风险操作，必须在界面与报告里明确写出两期日期。

## 十、与现有功能的衔接

- **监督分类页**：保存时带上 `method=SUPERVISED` 与 `accuracyJson`（OA/Kappa/混淆矩阵）
- **在线解译页**：保存时默认 `method=INDEX`（不改代码也兼容）
- **边界管理**：融合按 AOI 指纹归组，依赖已有 `aoiSignature`
- **安全评估 / 趋势**：融合结果作为普通解译记录参与，不影响现有算法
- **报告**：新增「地物分类与指数结果一致性」小节（P2）
